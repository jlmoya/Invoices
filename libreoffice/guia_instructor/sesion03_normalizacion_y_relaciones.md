## Errores frecuentes

| Síntoma | Causa | Solución |
| --- | --- | --- |
| HSQLDB rechaza crear la FK | Tipo distinto o hijo huérfano | INTEGER en ambos extremos; categorías existentes para todos los productos |
| No aparece una relación recién creada | Metadatos del editor desactualizados | Cerrar y reabrir Relaciones; no duplicar la FK |
| Clave compuesta quedó incompleta | En Diseño se seleccionó una sola fila | Revisar PRIMARY KEY ("IdFactura", "IdProducto") del SQL |
| Carga de factura falla por número repetido | Se importó dos veces | Comprobar filas existentes antes de repetir, sin borrar el conjunto correcto |
| Borrador tiene número 0 | La celda vacía fue convertida a cero | Corregir a NULL y revisar importación de Calc |
| Nueva factura recibe `IdFactura` 0 | La tabla se creó sin `START WITH 1` | Recrear `tblFacturas` vacía con `(START WITH 1)` antes de importar; tras los IDs explícitos, HSQLDB continúa en 8 |
| La cascada borró documentos de un cliente | Se configuró una cascada de más | Solo factura → detalle lleva ON DELETE CASCADE; restaurar copia de clase si hubo pérdida |

### Implementación posible de la solución

Se reutiliza `tblProveedores` de la tarea 2. Estas sentencias crean claves y relaciones con la única cascada esperada:

```sql
CREATE TABLE "tblPedidos" (
    "IdPedido" INTEGER GENERATED BY DEFAULT AS IDENTITY (START WITH 1) PRIMARY KEY,
    "NumPedido" VARCHAR(15) NOT NULL,
    "Fecha" DATE DEFAULT CURRENT_DATE NOT NULL,
    "IdProveedor" INTEGER NOT NULL,
    CONSTRAINT "UQ_Pedidos_Numero" UNIQUE ("NumPedido"),
    CONSTRAINT "FK_Pedidos_Proveedor" FOREIGN KEY ("IdProveedor")
        REFERENCES "tblProveedores" ("IdProveedor")
);
```

```sql
CREATE TABLE "tblDetallePedido" (
    "IdPedido" INTEGER NOT NULL,
    "IdProducto" INTEGER NOT NULL,
    "Cantidad" INTEGER NOT NULL,
    "CostoUnitario" DECIMAL(18,4) NOT NULL,
    CONSTRAINT "PK_DetallePedido" PRIMARY KEY ("IdPedido", "IdProducto"),
    CONSTRAINT "CK_DetallePedido_Cantidad" CHECK ("Cantidad" > 0),
    CONSTRAINT "CK_DetallePedido_Costo" CHECK ("CostoUnitario" >= 0),
    CONSTRAINT "FK_DetallePedido_Pedido" FOREIGN KEY ("IdPedido")
        REFERENCES "tblPedidos" ("IdPedido") ON DELETE CASCADE,
    CONSTRAINT "FK_DetallePedido_Producto" FOREIGN KEY ("IdProducto")
        REFERENCES "tblProductos" ("IdProducto")
);
```

Precio de venta y costo de compra no son intercambiables. La guía exige identificar las anomalías y justificar el modelo antes de ejecutar SQL.
